# ZBrain Governance SDK

A governance-first framework for building trusted AI systems.

zbrain-governance-sdk is designed to sit at the core of autonomous agent stacks, enforcing policy, logging actions, managing trust, and stopping unsafe behavior before it reaches production.

## Core Capabilities

- **Audit Logging**: Tamper-evident, append-only audit trails with support for merkle integrity proofs, search, export, and verification.
- **Trust & Identity**: Agent registration, decentralized identifiers (DIDs), Ed25519 keys, dynamic risk scoring, trust tiers, and short-lived capability credentials.
- **Callback Placeholders**: Runtime registration carries reserved bundle-update and kill-switch URL fields; callback handling and kill-switch enforcement are not implemented yet.
- **Rate Limiting**: Per-agent / per-ring token bucket enforcement with burst control and default limits for trusted and untrusted agents.
- **Prompt-Injection Validation**: One `validation_lifecycle` policy rule routes deterministic checks across user input, provenance-labeled model inputs, tool/retrieval results, and model-output canary leakage while retaining each concrete runtime checkpoint in the decision.
- **Policy Engine**: Declarative policy rules with allow/audit/warn/deny actions, deterministic evaluation, and conflict resolution.

## Project Direction

This repository is intended as a governance scaffold that can be embedded into larger systems. It follows the governance-first mindset emphasizing:

- real-time policy enforcement
- auditable decision recording
- trusted agent identity and lifecycle management
- safe rate-limited execution
- tamper-proof logging

## Package Usage

This is a private, file-based package rather than a registry-published
dependency. Check it out inside or beside the backend, build it, and reference
that directory from the backend's `package.json`:

```json
{
  "dependencies": {
    "@zbrain/governance-sdk": "file:./vendor/zbrain-governance"
  }
}
```

```bash
npm --prefix ./vendor/zbrain-governance ci
npm --prefix ./vendor/zbrain-governance run build
npm install
```

```ts
import { initializeGovernanceSDK } from "@zbrain/governance-sdk";
```

```js
const { initializeGovernanceSDK } = require("@zbrain/governance-sdk");
```

Node selects the matching ESM or CommonJS artifact automatically. Consumers do
not import from `src/`, `test/`, or `examples/`. The package name is still the
import specifier even though the dependency source is a local `file:` path.

## Local Submodule Development

This repository is meant to be added to a parent repo as a git submodule, for example:

```bash
git submodule add https://bitbucket.org/leewayhertz/zbrain-governance-sdk
git submodule update --init --recursive
```

Build the submodule, then add it to the parent as a local package dependency.
The parent application still imports `@zbrain/governance-sdk`; it never imports
files from the submodule's `src/` directory.
